# my-homework-site
Мой учебный сайт

## «Сумасшедшая наука» — проверочная версия v0.1

Адаптивный статический сайт по утверждённым материалам частей 1–3. Собственный домен, реклама, аналитика и приём заявок не подключены. Цены явно отмечены как предварительные.

### Запуск

Нужен Python 3. В корне репозитория:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory .
```

Это локальный сервер для разработки, а не ссылка для куратора. Установка зависимостей для работы сайта не требуется. Все ресурсы включены в проект; внешних шрифтов, библиотек и запросов к API нет.

### Браузерные проверки

Node.js 22+ и Python 3; тесты используют Playwright и Chromium:

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
```

Если Chromium уже установлен системно, тесты используют `/usr/bin/chromium`; можно задать другой путь через `CHROMIUM_PATH`. При наличии системного браузера установка браузера Playwright не нужна. Тесты самостоятельно запускают временный локальный HTTP-сервер. В ограниченной облачной песочнице для локальных сокетов и Chromium может потребоваться разрешённое выполнение за её пределами.

### Пакет публикации

До упаковки можно отдельно проверить размеры и отсутствие base64, не выводя содержимое файлов:

```sh
python3 scripts/check_assets.py
```

Проверка допускает до 400 КиБ на изображение и до 3 МБ суммарно для публичных файлов. Компактный отчёт с размерами и хешами сохраняется в `release/asset-report.json`. Упаковка также запускает эту проверку; при ошибке до сборки предыдущий рабочий архив сохраняется.

```sh
python3 scripts/package_site.py
```

Результат: `dist/` и `release/sumnauka-review-v0.1.zip`. Архив содержит только публичные файлы сайта, без документов курса, исходных вложений, тестов и зависимостей. Его можно разместить на согласованном статическом хостинге, сохранив структуру файлов.

Фотографии нужно хранить отдельными файлами в `assets/`, а не вставлять в HTML/CSS/JS в base64. Оригиналы сохранять вне публичной папки, для сайта готовить WebP-копии шириной до 1600 px и проверять качество/размер. Реальных JPG из утверждённых материалов во вложениях не было. До их получения используется авторская SVG-иллюстрация. Снимки проверочной страницы в `release/` не входят в сайт; для передачи подготовлены компактные WebP-копии, PNG-оригиналы сохранены. В ответах передавать ссылки и размеры, не содержимое бинарных файлов.

Для GitHub Pages в этом репозитории подходит источник **Deploy from a branch → main → / (root)**. Файл `.nojekyll` отключает ненужную обработку Jekyll. Включение Pages и наличие рабочей публичной ссылки требуют отдельной проверки; одна отправка файлов в GitHub не означает публикацию.

### Обновления и версии

Менять существующие `index.html`, `styles.css`, `app.js`, затем запускать `npm test` и повторно собирать архив. На хостинг передавать содержимое `dist/`, а не сам каталог. При GitHub Pages из `main` обновления публикуются после коммита и push в выбранную ветку. Утверждённые цены, состав и обещания менять только по решению владельца. Копирование плана — локальная функция, не отправка заявки.
