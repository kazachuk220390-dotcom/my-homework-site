# Подключение отдельного поддомена new.sumnauka.ru к GitHub Pages

## Цель
Сохранить старый сайт https://sumnauka.ru/ на Tilda **без изменений** и подключить отдельный новый сайт из репозитория `kazachuk220390-dotcom/my-homework-site` к адресу `new.sumnauka.ru`.

Новый сайт уже публикуется (при активной публикации GitHub Pages) на `https://kazachuk220390-dotcom.github.io/my-homework-site/`. Покупать второй платный проект Tilda для GitHub Pages не нужно.

## Что уже выяснили
- Репозиторий `kazachuk220390-dotcom/my-homework-site` публичный, есть права администратора.
- На 10 ноября 2026 в корне репозитория отсутствует файл `CNAME`; выделенный поддомен ещё не активирован.
- У показанного аккаунта REG.RU нет доступных услуг. Это не значит, что домен не зарегистрирован: он может числиться за другим аккаунтом или у другого регистратора.
- На Tilda старый сайт остаётся без изменений.

## Что нужно выяснить перед включением нового адреса
1. Где именно обслуживаются авторитетные DNS-записи `sumnauka.ru` (NS-серверы)? Tilda DNS, REG.RU или другая компания?
2. Кто имеет доступ к редактированию DNS-записей?
3. Есть ли уже отдельная запись для `new.sumnauka.ru`? Нельзя затирать чужую запись без проверки.
4. Если DNS управляет Tilda, умеет ли текущая панель добавить произвольную запись CNAME для GitHub Pages? В стандартном разделе «Дополнительные записи» документация Tilda описывает TXT/MX, а создание поддомена внутри Tilda может требовать дополнительного проекта. **Не покупать новый тариф без проверки альтернативного управления DNS.**

## Безопасная целевая настройка
**Только поддомен:**

| Поле | Значение |
|---|---|
| Поддомен | `new.sumnauka.ru` |
| Тип | `CNAME` |
| Имя / Host | `new` (иногда требуется `new.sumnauka.ru`) |
| Значение / Target | `kazachuk220390-dotcom.github.io` |
| TTL | автоматический / по умолчанию |

Указывать `kazachuk220390-dotcom.github.io` **без** `/my-homework-site`. Не изменять DNS-записи для `@`, `sumnauka.ru`, `www` или почты.

После согласования управления DNS в GitHub: репозиторий → Settings → Pages → Custom domain → `new.sumnauka.ru`; если GitHub Pages публикуется из ветки, будет создан корневой файл `CNAME` со строкой `new.sumnauka.ru`.

**Не включать Custom domain/не добавлять `CNAME` заранее**, пока не подготовлена DNS-запись: существующий адрес GitHub Pages может начать перенаправлять на ещё не работающий поддомен.

## Если DNS сейчас у Tilda и нельзя добавить CNAME
Не нужно создавать второй платный сайт Tilda. Вместо этого можно поручить специалисту перенести **только управление DNS** к поддерживающему CNAME провайдеру (например, к регистратору или в отдельную DNS-службу). Важно заранее скопировать и перепроверить все существующие A/AAAA, CNAME, MX, TXT, SPF, DKIM и другие необходимые записи, иначе можно нарушить работу старого сайта или почты. **Не менять NS и не переносить домен без резервной копии DNS-зоны и отдельного согласования.**

## Проверки после настройки
- `sumnauka.ru` и `www.sumnauka.ru` по-прежнему открывают старый Tilda-сайт
- `new.sumnauka.ru` открывает новый сайт на GitHub Pages
- HTTPS для нового адреса доступен, после распространения DNS включена опция Enforce HTTPS
- Нет переадресаций нового адреса на основной старый сайт
- Проверены мобильная версия, изображения и анимации, калькулятор и контактные кнопки
- Конкретные DNS-записи старого сайта нигде не изменены без разрешения
